# Applying Diátaxis to existing documentation

Use Diátaxis as a **guide**, not a top-down plan. Its four-part structure helps assess direction; it is not a template to impose before useful content exists.

Start applying the model as soon as one principle is useful. Understanding develops through alternating between documentation work and reflection on that work.

## Let structure follow quality

Improve the internal components first. Well-formed tutorials, how-to guides, references, and explanations will create pressure for an appropriate larger structure.

Do not begin remediation by:

- creating four empty top-level sections;
- moving pages solely to make the navigation resemble the Diátaxis map;
- planning a complete rewrite before publishing any improvement; or
- treating the four quadrants as a completeness checklist for every product.

Restructure when improved content makes the new boundary or grouping necessary. The information architecture should emerge from documents that each serve a clear reader need.

## Work in a small loop

1. **Choose one thing.** Start with the page, paragraph, or sentence already in front of you. Prefer a small unit.
2. **Assess it.** Identify the reader need with the compass. Check whether its language and logic fit that quadrant. Ask what should be added, moved, removed, or changed to serve the need better.
3. **Choose one improvement.** Select the smallest action that produces an immediate, observable gain.
4. **Complete it.** Make that change ready to publish rather than holding it for an imagined comprehensive revision.
5. **Repeat.** Let the completed change reveal the next useful action.

This loop removes the need to solve the entire documentation system before improving any of it. Use broader planning only where external delivery constraints genuinely require it.

## Complete, not finished

Living documentation is never finished: products and reader needs continue to change. It can still be complete at every stage—useful now, appropriate to its current scope, internally healthy, and ready for the next improvement.

Judge the current change by whether it leaves the selected material complete for its stated reader need, not whether the whole documentation set has reached a final state.
